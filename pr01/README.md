# Практическая работа №1 — Операционные системы

## Вариант C: исследование systemd и автоматизация задачи

### 1. Цель работы

Изучить управление системными службами в Linux, настроить автоматический запуск Python-скрипта с помощью systemd, просмотреть системные журналы и измерить время запуска системы.

Работа выполнена в Ubuntu 26.04 LTS в среде WSL2 на Windows 11.

### 3. Python-скрипт

Файл `logger.py` записывает текущую дату и время в `results/time.log` каждые 10 секунд.

Для записи используется Python, модуль `datetime` получает текущее время, а `time.sleep(10)` задаёт интервал между записями.

Запустить скрипт вручную можно командой:

```bash
python3 logger.py
```

Остановить ручной запуск: `Ctrl+C`.

### 4. Настройка службы systemd

Для автоматического запуска создана служба `time-logger.service`.

Основные параметры службы:

* `Description` — описание службы.
* `User=bekish` — пользователь, от имени которого запускается скрипт.
* `WorkingDirectory` — рабочая папка проекта.
* `ExecStart` — команда запуска Python-скрипта.
* `Restart=on-failure` — повторный запуск при аварийном завершении.
* `WantedBy=multi-user.target` — цель, для которой служба включена в автозапуск.

Служба включена и запущена командами:

```bash
sudo systemctl daemon-reload
sudo systemctl enable time-logger
sudo systemctl start time-logger
```

Проверка состояния:

```bash
systemctl status time-logger --no-pager
```

Результат: служба имеет состояние `active (running)`, а параметр автозапуска — `enabled`.

### 5. Просмотр журналов

Для просмотра последних сообщений службы используется команда:

```bash
journalctl -u time-logger --no-pager -n 10
```

Журнал показывает время запуска службы и сообщения, которые выводит Python-скрипт.

### 6. Измерение времени запуска

Для анализа использовались команды:

```bash
systemd-analyze
systemd-analyze blame
systemd-analyze critical-chain
```

Результат `systemd-analyze`:

```text
Startup finished in 2.027s (userspace)
graphical.target reached after 2.026s in userspace.
```

Измеренное время достижения `graphical.target` составило около 2,026 секунды.

Работа выполнялась в WSL2, поэтому эти значения относятся к системной среде Linux внутри WSL, а не ко всему запуску Windows.

В списке `systemd-analyze blame` были обнаружены службы с заметным отображаемым временем запуска, в том числе `motd-news.service`, `landscape-client.service` и `snapd.seeded.service`.

Возможная оптимизация: проверить, нужны ли службы получения новостей и управления Landscape. Отключать службы следует только после проверки их назначения и зависимостей. Время `wsl-pro.service` оказалось аномально большим по сравнению с общим временем запуска, поэтому его нельзя напрямую считать временем задержки загрузки системы.

### 7. Сравнение systemd и OpenRC

| Критерий             | systemd                                       | OpenRC                                        |
| -------------------- | --------------------------------------------- | --------------------------------------------- |
| Основное назначение  | Управление службами и системными компонентами | Управление службами и их запуском             |
| Конфигурация         | Unit-файлы                                    | Скрипты служб и конфигурация OpenRC           |
| Управление службами  | `systemctl`                                   | `rc-service`                                  |
| Автозапуск           | `systemctl enable`                            | `rc-update add`                               |
| Журналы              | Обычно доступны через `journalctl`            | Часто используются syslog и отдельные журналы |
| Пример использования | Ubuntu и многие другие Linux-дистрибутивы     | Alpine Linux и другие системы с OpenRC        |

Сравнение OpenRC выполнено теоретически. В рамках этой работы OpenRC отдельно не устанавливался и экспериментально не проверялся.
